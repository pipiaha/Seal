# 助手上下文、补充要求与恢复

实现沿用官方 pi 0.87.1 SessionManager 和指令队列，不增加独立对话数据库或模型执行循环。

## 使用方式

助手开始处理后，输入框仍可写字，“发送”变为“补充要求”，停止按钮继续保留。
例如发送“字幕改成白色，其他继续”，界面先显示等待当前步骤结束，模型实际读取后显示已交给助手。
工具已经提交的外部生成不会被这句话自动取消；新增素材或切换技能在下一轮发送。

断流后界面核对同一回合记录；重新打开页面也会发现尚在执行的回合。重开软件后，中断回合会显示已完成工具和未处理要求。
继续制作时读取原工作流、任务和候选，复用现有结果。已完成成果不因对话中断回滚。

## 实现边界

- `assistant_context.go` 从已有归属校验后的画布生成有限概览；剪辑上下文由运行端读取原生选区、工程概览及最近修改。
- `turn-context.mjs` 包装已有工具：保存私有长结果、提供分页/搜索，并将操作身份和完成状态写入官方会话。
- `turn-instructions.mjs` 使用 `sendUserMessage` 的官方 steering 队列，关闭模板/技能命令展开；编号用于同一要求的网络重试去重。
- Go 的 `/assistant/steer` 与宿主双重校验工程、会话和当前回合，不扩大冻结权限。
- 运行端使用独立回合预算；分页读取不会绕过工具预算。
- 候选的起始版本继续固定，人工改动不会通过恢复自动覆盖。正文与版本在同一锁内读取。
- 此次不修改模型能力默认值，不启动新的付费模型调用，也不发布新的安装包。

## 针对性验证

验证使用本机模拟模型，不产生模型或生成费用：

- 官方 SDK 实际接收同一回合的补充指令；重复编号只入队一次，其他轮次拒绝。
- 停止后要求保留为未处理，清空队列，下一回合不再次执行。
- 官方会话文件重新打开后，成功工具的回执、任务 ID 和长结果可恢复；路径越界拒绝。
- 后端入口校验当前用户、尚未结算的回合和 UI 凭据；概览排除正文与数据 URL。
- 前端确认接纳的轮次 ID 用于断流恢复，避免相同文字匹配到其他回合。
- 浏览器模拟回合验收等待/已交给助手状态、断流追踪和历史恢复。

真实模型能否正确完成字幕修改等制作要求，仍需用户用自己的渠道进行验收。恢复机制保留回执并阻止自动重放，不承诺外部供应商一定完成或取消已受理的任务。
