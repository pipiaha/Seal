# 本地 HTTP API

Wails 和浏览器开发模式共用同一套 `127.0.0.1` HTTP 合同。路由由 `backend/internal/handler/api.go` 统一注册，权威 OpenAPI 文件为 `backend/internal/handler/openapi.yaml`。

## 合同规则

- 无登录、Cookie 会话或租户选择；后端从本地 workspace context 解析唯一 owner。
- 成功响应为 `{ "code": 0, "data": ... }`；错误响应保留结构化 `code/reason/msg`。
- 写入接口限制 body 大小并校验资源归属；不信任前端提供的文件路径、模型能力或 provider 状态。
- 外部模型密钥由本地 provider config 管理，不在 API 日志或任务列表中返回。

自定义模型服务的配置仍由受保护的工作区配置接口提供给当前界面；运行时内存和生成请求可能包含凭据。浏览器持久配置缓存不保存 API Key、Secret Key 或自定义 Header，启动后从后端加载。内置 BeefAPI 继续使用后端凭据引用。配置导出会遮盖密钥和 Header 值；回填脱敏标记时必须匹配原渠道与 Header 名称，不能借用其他渠道的密钥。

模型目录通过本地后端读取。模型测试使用正常任务入口，等待最终文本或媒体结果才显示通过；测试会产生供应商费用，须先确认。测试结果不证明画布回填、媒体解码或最终账务结算。

`POST /assistant/ui-session` 返回仅驻留内存、绑定当前 owner 的 `token` 与 `expiresAt`。界面在到期前 30 秒重新签发凭据，同一身份的并发请求共用签发结果；重置或切换身份后旧响应不能恢复旧凭据。签发仍要求原有本机同源与 owner/桌面引导校验。

`POST /assistant/chat` 的响应头 `X-Beeftv-Turn-Admission` 区分 `rejected`（尚未调用业务轮次入口）、`unknown`（已经尝试开始轮次）与 `admitted`（已创建轮次）。仅明确的 `rejected` 或尚未发送消息的签发失败可按未接纳处理；缺少标记、网络错误或接纳后的断流仍需读取回执与画布确认。凭据续签和 403 失效处理都不会自动重放消息。

## 核心路由组

生成任务提交若包含当前渠道无法读取的本地素材，返回 HTTP 400、`reason=reference_media_requires_url`，不创建任务。`msg` 包含受影响素材的类型和序号；客户端可引导用户替换 HTTPS 链接或切换渠道。执行参数中的声音、水印等开关接受布尔值及其字符串形式，已有任务的同类参数也按相同规则读取。

`canvas.generation.propose` 是只读操作，返回的 `source` 包含 `canvasId`、`canvasRevision`、`modelConfigRevision`；模型键与配置版本来自同一次配置读取。提案不创建生成任务。

首次确认同时核对这两个持久版本、未保存的编辑和确认期间的变化。旧历史中没有 `source` 的提案需要重新提出。通过核对后，生成沿用已有模型解析规则，并使用确认时复制的提示词、节点、连线和全局参数。此版本合同不包含素材库独立更新、hydrate 时解析的动态角色版本或任意远端 URL 的内容字节变化。

| 路由组 | 用途 |
| --- | --- |
| `/workspace/*` | 本地工作区启动和模型配置 |
| `/beefapi/connection*` | 内置 BeefAPI 企业连接：开始、状态、取消、断开；页面只收到账号和状态，收不到密钥 |
| `/canvas-projects/*`, `/projects/*` | 画布、项目、章节、分镜与快照 |
| `/resources/*` | 本地素材、分片上传和媒体读取 |
| `/timeline/render-plan` | 只读编译时间线语义渲染计划：不排队、不落盘、不计费 |
| `/timeline/renders`、`/timeline/transcriptions` | 本机时间线成片任务与字幕转写任务 |
| `/depth-captures` | 本机深度动作捕捉任务 |
| `/tasks/*` | 生成任务创建、查询、取消、恢复与事件流 |
| `/ai/*` | 外部模型目录和自定义协议转发 |
| `/plugins/*`, `/skills/*` | 本地扩展包与技能 |
| `/skill-hub/*` | 本地 Skill 导入、查看、启停、更新和卸载 |
| `/creation-conversations/*` | `/create` 页面对话的提交事实：按对话 CAS 读写、导入与墓碑删除 |
| `/ops`, `/ops/:op` | 统一操作层：CLI、MCP 与内置 pi 会话共用同一组操作与校验 |
| `/ops/clients*`, `/assistant/*` | 外部客户端登记、内置创作助手（同源代理）与宿主生命周期 |
| `/health/*`, `/system/version` | 启动、就绪与版本诊断 |

`POST /timeline/render-plan` 接收时间线快照、不透明源标识和输出选项，返回版本化语义计划。源标识是 nodeId 或 resource id，不是本地路径。请求不得携带 ffmpeg 参数。该接口不做生成、不写资源、不创建任务。

`POST /timeline/renders` 接收同一套时间线快照和输出选项（宽高、帧率、采样率、是否烧录字幕），创建本机 ffmpeg 成片任务。选项进入任务输入并在执行时编译进语义计划。

`POST /timeline/transcriptions` 接收待转写素材编号和可选语言，创建本机字幕转写任务。只接受当前用户已上传完成的音视频。

`POST /depth-captures` 接收待处理视频素材编号，创建本机深度动作捕捉任务。只接受当前用户已上传完成的视频。

这些任务在本机完成，提交时不用挑选模型。请求可以带 `clientOperationId`：同一确认重复提交会回到原来的任务；同一确认换成不同内容会被拒绝，不会再新建一条。

## 助手输出预算与思考

`GET /assistant/status` 的 `model` 附带 `maxOutputTokens`、`contextWindow`、`reasoningFormat` 与 `reasoningEffort`（不含密钥）。文字模型执行参数通过既有工作区模型配置保存；`model_parameters_invalid` 表示输出或思考参数无效，不能静默切换模型。

助手默认单次预算为49152 Token，包含思考与正文；不是任务总预算。SDK负责协议映射：Chat Completions 的 `max_tokens` / `max_completion_tokens`，Responses 的 `max_output_tokens`；DeepSeek思考开关使用 `thinking.type`，启用时发送 `reasoning_effort`，关闭时不附带力度。Claude按配置使用预算或自适应格式。已保存的模型输出上限取较小值，SDK再按剩余上下文限制请求。上游拒绝配置时保留错误，不自动付费探测上限或改用另一渠道。

流式生命周期增加 `thinking` / `thinking_end`；不向页面传内部思考正文。`retry` 可带 `reason=model_output_truncated`，表示一次有限续接：仅在纯思考截断、未取消且无待审批或等待任务时执行，共用原轮次预算、操作回执和期限。再次截断返回 `model_output_truncated`；部分正文或工具参数不自动拼接。`model_response_aborted` 表示上游中断。默认整轮期限15分钟，无模型内容或进度超过3分钟返回 `model_idle_timeout`；工具执行期间暂停模型空闲计时，工具保留自己的超时和停止处理。

## 本地 Skill Hub

所有请求使用当前工作区身份。内置 `beeftv-editing`、`hypit`、`hyperframes`、`video-use`、`skill-creator` 允许查看和启停；用户包不能覆盖内置标识。

| 请求 | 合同 |
| --- | --- |
| `GET /skill-hub` | `{ skills }`，含来源、启停、当前版本、文件数与诊断 |
| `POST /skill-hub/inspect` | multipart `file`、可选 `name` / `description`；返回入口预览、规范化哈希、缺失元数据与同名冲突 |
| `POST /skill-hub/install` | 同一文件和元数据、预览 `contentHash`、`enabled`；更新须明确 `targetId`，保留启停状态 |
| `PATCH /skill-hub/:id/enabled` | `{ enabled: boolean }`，最多同时启用 64 个 Skill |
| `DELETE /skill-hub/:id` | 卸载用户安装包；不删除作品 |
| `GET /skill-hub/:id/files` | `{ files }` 文件索引 |
| `GET /skill-hub/:id/file?path=…` | `{ file, content, binary }`，路径必须属于该包 |

文件选择器接受本地 Markdown/ZIP；单包解压总计 20MB，单文件 8MB，最多 512 文件，入口文本 512KB。导入不执行脚本、不安装依赖。Agent 请求由 Go 覆盖注入当前用户的可信 `skillSnapshot`；普通页面不能指定读取根目录。SDK 会话仅在轮次间刷新，同一轮固定版本，受限 `read` 和 `hypit_read(area=skill)` 均遵守该快照。回合 `skillsUsed` 记录通过这些工具读取、或由显式选择在运行前完整加载的技能，页面展示“本轮已读取技能”。

`POST /assistant/chat` 可带 `selectedSkillId`，每条消息最多指定一个技能。Go 在创建业务轮次前核对当前用户的已启用技能快照；不存在、停用或不可用时返回 `selected_skill_unavailable`，不转发模型请求。运行端从该快照的目录读取完整 `SKILL.md`，按当前版本处理本轮，并按需通过受限 `read` 获取引用文件。客户端不能提交目录或说明内容替代可信快照。`turn_end` 与官方会话历史中的 `requestedSkill` 保存指定技能的 ID、名称、显示名称、版本及内容哈希；自动选择仍由 Agent 按需求决定，历史轮次的指定不自动延续。

### 助手制作扩充

`POST /assistant/chat` 支持 `images: [{id,name,mimeType,data,source?}]`；`data` 是 PNG/JPEG 的 Base64，不能用文件路径或素材编号替代图片内容。图片是用户提供的观察，不增加文件或工具授权。后端在接纳回合前校验实际图片格式、像素、数量和大小；失败返回 `image_input_invalid`。产品上限为 8 张、合计 12 MiB，单图及数量还受所选模型 `capabilityConfig.text.references.maxImages/maxImageBytes` 限制。新配置及未填写图片参数的已有模型默认允许 8 张、每张 4 MiB；显式将数量或大小设为 0 时关闭图片输入。状态接口的 `model.maxImages/maxImageBytes` 返回当前有效限制，配置变化会更新宿主。

运行端通过官方 pi `prompt(...,{images})` 发送附件，通过官方供应商适配器转换 OpenAI Chat、Responses 和 Anthropic 图片内容。官方会话保存真实图片，回合历史只返回附件名称、来源等元数据。请求投影保留最新图片并限制整个请求的图片总数，不修改保存的会话；旧附件可通过当前会话范围内的 `conversation_image_read` 重新读取。附件不能在运行中补充指令时追加，需在下一轮发送。

剪辑页的“附上当前画面”读取播放位置，“附上选中片段”读取选中片段中点的合成画面；`@` 工程图片/视频解析成原素材画面，音频继续走转写。`POST /edit-projects/:canvasId/edits/:editId/vision` 接受 `{time?,clipIds?,file?,expectedRevision?}`。运行端验证工程范围、素材路径及片段时间，冻结工程快照后用钉选的 HyperFrames CLI 读取合成画面，媒体解码走随软件打包的 FFmpeg。返回 `{editId,revision,images:[{mimeType,data,time,file}]}`。截图临时目录完成后清理，不写入剪辑轨道或导出结果。

Agent 的 `edit_view` 复用这个读取入口：支持指定时间、当前选区或工程内素材，返回真实图片及时间/版本信息。工具返回图片也校验模型限制；视觉能力关闭时明确报错，不能将“读到工程代码”当作“看到画面”。

以下 POST 均在 `/assistant/projects/:projectId` 下，要求受信任的桌面界面或有效的当前工程宿主轮次；外部客户端不能借用宿主或 UI 身份。

| 路径 | 合同 |
| --- | --- |
| `/skills/list`、`/skills/file` | 读取当前用户 Hub 和包内文件；读取不启用脚本 |
| `/skills/author` | `files` 文本映射、`save`、`enabled`；更新另带 `targetId` 与 `expectedTargetHash`。格式验证不等于行为验证，保存后下一轮加载 |
| `/skills/search` | `query`；搜索公开 GitHub 仓库，命中项尚未验证 |
| `/skills/download` | `url`、可选 `ref/subdir`、`enabled`；更新须当前摘要。保存实际 commit，无依赖安装和自动升级 |
| `/media/asr-status` | 本地模型及已有转写服务就绪状态，不返回路径、地址或密钥 |
| `/media/transcribe` | 引用的 `assetId`、可选 `language` 和 `route=local/service`。生成或复用 `timeline_transcription` 任务；资源、语言、工程、运行配置共同确定身份 |
| `/media/transcription` | `taskId`；读取当前工程 ASR 状态及持久结果，`timingLevel=token` 为近似 token 对齐 |
| `/media/propose`、`/media/proposals` | 提出或读取图片、视频、配音方案；不提交上游生成 |
| `/media/accept/:proposalId` | **仅受信任界面**确认生成；接收现有 `CreateTaskInput`，核对提示词、模式与模型版本，使用固定提交编号；宿主不能代确认 |
| `/media/task` | 读取当前工程已接受方案的任务及素材交付状态；重开后查询原任务 |

`GET /assistant/asr` 返回本地识别就绪状态及脱敏的 `settings`。`PUT /assistant/asr` 由受信任桌面界面保存配置，包含 `revision`、`defaultRoute`（auto/local/service）、`language`、`serviceEnabled`、`serviceType`（whisper/openai）、`baseUrl`、`model`、`apiKey`、`hasApiKey`。保存时检查版本；密钥留空且 `hasApiKey=true` 保留原密钥，设为 false 则清除。配置加密保存在工作区 `asr-settings.json`，读取仅返回密钥是否存在，助手不能修改该配置。在线 OpenAI 兼容转写调用 `/audio/transcriptions`，Whisper.cpp 服务调用 `/inference`；需要支持带句段时间戳的 `verbose_json`，不自动重试为另一项付费服务。服务地址遵循自定义上游校验，仅 Whisper.cpp 的显式回环服务允许直接访问。

本地 Windows 运行包使用 whisper.cpp CPU `1.9.2` 和多语言 Base，模型实际 147951465 字节；自动模式优先本地模型，尚未保存配置时读取 `CANVAS_WHISPER_BASE_URL` 作为已有服务。识别任务按实际运行端与配置生成不含密钥的指纹，排队期间服务或密钥变化会要求重新提交。时间戳包括句段及近似 token，不能承诺精确逐字切点。
同一官方会话新增 `workflow_read` 和 `workflow_checkpoint`；多步生成按真实 `workflowId/stepId` 固定提交身份。步骤记录不代替运行端状态或付费确认。

## 统一操作层与内置创作助手

### 工程文件、脚本与联网工具

`GET /assistant/web-settings` 返回脱敏 `settings`（enabled、provider=tavily/deepseek、credentialSource=manual/channel、channelId、baseUrl、model、maxResults、configured、可选 configurationError）和 `runtime`（sandbox=false、executionMode=full-access、node、python、scope=current-os-user、network=system-network、maxSeconds）。`PUT` 仅接受可信桌面界面，输入以上可写配置与可选 apiKey、clearKey；两家独立密钥分别加密保存，留空保留当前服务原密钥，clearKey 仅清除当前服务独立密钥。DeepSeek 渠道复用每次读取当前渠道密钥，停用、删除或缺少密钥明确失败；搜索地址独立于聊天地址，必须是公开 HTTPS 基础地址。宿主不能修改该配置。

`POST /assistant/web-test` 仅允许可信界面，输入 `{query}`，使用已保存且启用的搜索配置，返回 provider、sources 和引用提示。此入口执行真实服务调用并支持取消，不接受临时密钥或模型指定，不允许 Agent 宿主调用。无搜索结果块、上游拒绝、配置缺失等返回真实失败。

搜索失败投影为可公开的业务错误：HTTP 400 用于配置或关键词无效，502 用于网络失败、供应商拒绝及响应格式错误，504 用于搜索超时。`reason` 区分 `web_search_network_failed`、`web_search_timeout`、`web_search_provider_rejected`、`web_search_response_invalid`、`web_search_native_failed` 与 `web_search_no_native_results`；`msg` 给出中文原因及检查方向，不包含密钥、上游原始响应体或内部网络异常。官方搜索域名的本机 TUN Fake-IP 兼容仅作用于搜索连接，不改变网页读取与下载的地址策略。

下列 POST 路径均位于 `/assistant/projects/:projectId`，沿用当前用户工程归属和本机可信身份验证；助手宿主必须提交匹配当前工程的开放轮次。文件及脚本不使用计费生成的批准模式。

| 路径 | 合同 |
| --- | --- |
| `/workspace/info` | 工程 Agent 工作目录与实际解释器 / 隔离能力 |
| `/workspace/files` | action=list/read/write/mkdir/remove/search、path 相对路径；write/remove 已有文件携带 expectedHash；read 可带字节 offset；文本单页 512 KiB |
| `/workspace/skill` | name、contentHash；复制当前启用的匹配版本技能，不修改原包 |
| `/workspace/run` | runtime=node/python、script 相对路径、args 字面参数、timeoutSeconds≤120、operationId；返回退出码、状态和限长输出；中断回执不自动重放 |
| `/workspace/runs` | 最近执行回执摘要，最多 100 条；结果不代替原生工程历史 |
| `/workspace/install` | runtime、packages 包名及可选版本、operationId；工程 npm（禁用安装脚本）或 Python .venv |
| `/workspace/asset` | assetId、path；复制当前用户素材为新工作文件 |
| `/workspace/publish` | path、可选 title；通过资源校验导入图片 / 视频 / 音频到资产库，按内容去重 |
| `/assets/search` | query、kind、page；检索当前用户资产元数据，每页 30 条；素材理解另用 media_read / ASR |
| `/web/search` | query；按用户配置使用 Tavily 或 DeepSeek 原生搜索，返回 provider 与真实来源列表；无密钥、未启用或无原生搜索结果明确失败，不自动切换服务 |
| `/web/read` | url、可选 offset；公开 HTML/text/JSON，每页 20,000 字节，返回来源和 nextOffset |
| `/web/download` | url、path；公共地址文件存入新工作文件，最多 256 MiB |

脚本默认使用当前系统账户的普通进程完全访问本机，工作目录不是文件或网络沙箱；运行环境不注入应用密钥。Windows Job Object、macOS/Linux 进程组用于停止和超时清理，其他平台拒绝执行。原生素材导入不要求本轮事先引用，但仍检查当前用户资产及工程归属，入轨和撤销保留版本保护。公共页面工具仍拒绝内网、回环、保留 IP 和危险重定向；完全访问脚本使用系统网络权限，两者范围不同。详见 [Agent 工作目录、脚本与联网](/agent-workspace.md)。

`DELETE /assets/:id` 校验素材归属及业务引用。清空回收站时传 `expectedStatus=archived`，在删除事务内再次检查状态；期间已经还原的素材返回 409 并保留。该参数只接受 `archived`，其他值返回 400。省略参数保留普通删除语义，仍须通过引用检查。

`GET /ops` 返回调用者当前身份可用的操作描述（含 JSON Schema）；`POST /ops/:op` 执行单个操作。
写操作必须带 `opId` 作为幂等键（同一 `opId` 同参数回读原结果，不同参数返回冲突），并按操作声明的
`expectedRevision` 做原子 CAS：缺少读取时的 revision、或 revision 已过期，都会被拒绝，不会覆盖别人刚写入的内容。
字段落点由画布能力描述符声明（例如生成类节点的可编辑提示词落在 `metadata.composerContent`，也就是画布编辑器
读取的字段），操作层不自行拼文档形状。

参数解析在所有层上都严格：顶层以及 `patch`、`nodes` 等嵌套对象出现未知字段时整批拒绝（`unknown_field`），
不会部分执行却推进 revision。schema 声明的 `params.operationId` 与请求信封的 `opId` 同时出现而又不一致时返回
`operation_id_conflict`，不会自行挑选其中一个身份。外部 MCP/CLI 的能力描述保留 `operationId` 作为稳定幂等键；
内置助手宿主自己生成幂等键，因此它看到的能力描述不含该字段。

### 助手回合归属

内置助手宿主调用 `/ops/:op` 时出示自己的宿主凭据 `X-Beeftv-Agent-Token`（由后端注入宿主进程，页面与
外部客户端拿不到），并带上后端在 `/assistant/chat` 中签发、随转发体下发的 `X-Beeftv-Agent-Turn`。
后端按该回合记录读取这一轮被验证过的范围，而不是信任任何调用方自报的列表：

- 会话默认范围是当前画布，加上当前画布文档里真实关联的素材与生成任务（沿用画布既有的媒体引用解析）。
- 界面上明确 @ 引用或附加的素材、画布在对话入口逐项校验归属后写入回合记录；额外画布只读。
- 跨画布写、读取与当前画布无关的素材/任务都返回 `scope_denied`；工作区级列举（`asset.list`、`canvas.search`）不暴露给助手。
- 已登记读写客户端与 owner 直连保持原有工作区读写能力；它们即使拿到 `turnId` 也不能出示归属，带上回合头会被拒绝。
- 回合只在开启期间接受归属；结算或撤销之后不再接受新写入，模型侧也无法自己生成授权。

内置创作助手的浏览器侧只使用同源代理：

`POST /assistant/chat` 可带 `images: [{id,name,mimeType,data,source?}]` 与 `media: [{id,name,kind,assetId?,nodeId?,content?}]`。
图片为 PNG/JPEG base64，需模型开启视觉并满足图片大小/数量限制。`media.kind` 为 `video/audio/text`；音视频须选择所属且在本轮已验证的资产，或当前画布节点；文字只支持 UTF-8 常见文字/字幕文件，最多 16000 字符/个、64000 字符/轮。元信息由后端校验并规范化。
历史中的 `images/media` 不重复保存像素和文字正文，官方会话日志保留实际 SDK 输入。当前运行端原生支持文字与图片，视频通过真实抽帧及 ASR，音频通过 ASR；不代表原生视频/音乐理解。

| 多媒体端点 | 说明 |
| --- | --- |
| `POST /assistant/projects/:projectId/media/read` | `{assetId? 或 nodeId?, frames?, times?, count?}`；读取真实时长、尺寸与音轨；视觉模型可抽取真实 JPEG，默认 3 个时间点，受模型图片数量限制 |
| `POST /assistant/projects/:projectId/media/transcribe` | `{assetId? 或 nodeId?, language?, route?}`；创建或复用持久 ASR 任务，返回 `taskId/status/stage/progress`；不把开始任务当转写成功 |
| `POST /assistant/projects/:projectId/media/transcription` | `{taskId}`；查询所属工程的真实任务与转写结果，时间为原素材时间 |
| `POST /edit-projects/:projectId/edits/:editId/vision` | `{file?, time?, times?, clipIds?, count?, expectedRevision?}`；有版本保护的真实画面读取。`times` 仅用于视频文件原素材时间；`time` 用于工程合成画面；片段选区使用中间时刻 |
| `POST /edit-projects/:projectId/edits/:editId/media-info` | `{file, expectedRevision?}`；当前工程真实音视频信息和 `placements`（入点、速度、变速曲线） |
| `POST /edit-projects/:projectId/edits/:editId/transcribe` | `{file, expectedRevision?, language?, route?}`；校验已固定的工程资产引用和原文件哈希，转写所属原资源，返回持久任务及原素材到时间线的位置信息 |

以上端点沿用可信本机界面/开放助手回合与所属工程检查。抽样仅证明看过返回的时间点；ASR 仅转写讲话。完整范围与验证见 `docs/refactor/assistant-multimodal-audit.md`。

### 助手生成权限与结果续接

输入框的“请求批准 / 完全允许”按用户、工程和官方会话 `sessionId` 保存；新对话默认 `ask`。
这里只管理助手提交的图片、视频和配音生成，不扩大素材读取范围或授予脚本执行能力。

| 端点 | 合同 |
| --- | --- |
| `POST /assistant/projects/:projectId/permissions/read` | `{sessionId}`，返回 `{mode: "ask" 或 "allow"}` |
| `POST /assistant/projects/:projectId/permissions/write` | `{sessionId, mode}`；只能由可信本机界面修改 |
| `POST /assistant/projects/:projectId/permissions/stop` | `{sessionId}`；持久关闭这条对话尚未续接方案的自动制作/续接，权限模式不变 |
| `POST /assistant/projects/:projectId/permissions/resume` | `{sessionId}`；界面在用户主动发起下一轮前恢复允许新方案，保留旧已停止方案的状态 |
| `POST /assistant/projects/:projectId/media/propose` | `{operationId, kind, prompt, model?, sessionId?}`；方案包含 `sessionId/decision/autoContinue/continuationTurnId`；宿主注入真实会话标识 |
| `POST /assistant/projects/:projectId/media/proposals` | 返回所属工程的方案，界面只展示当前对话与旧无会话方案 |
| `POST /assistant/projects/:projectId/media/accept/:proposalId` | 使用现有任务创建入参并附加 `automatic`；手动批准为 `false`，自动提交为 `true`。后台校验所保存模式为 `allow`、方案未停止或拒绝、模型配置与方案一致；沿用稳定任务回执 |
| `POST /assistant/projects/:projectId/media/reject/:proposalId` | 拒绝尚未开始提交的方案；拒绝与批准通过持久决定互斥 |
| `POST /assistant/projects/:projectId/media/task` | `{taskId}`；读取所属方案任务、产物物化状态和实际素材 ID |

停止标记也持久保存；停止之后晚到的方案不能因刷新而自行恢复生成。
宿主凭据不能调用 `permissions/*`、`accept/*` 或 `reject/*`，Agent 无法给自己授权。
审批失败、配置变化、结果未准备好均不能静默放行。`ask` 下明确点击批准后，界面也会继续跟踪实际任务结果。

`POST /assistant/chat` 的自动续接携带原 `sessionId` 和 `continuationProposalId`。后端校验原方案、真实终态和 `READY` 产物，
将实际产物写入新回合授权范围，并原子登记 `continuationTurnId`；同一结果不能重复受理，拒绝/失败结果可不带素材续接。
登记代表回合已受理，不能当成助手已成功完成后续剪辑。断流或宿主不可达时沿用现有历史读取与继续执行入口，不能自动重放未知结果。

自动提交与续接由打开的助手界面协调；软件关闭时生成任务保留，重新打开原对话可继续处理尚未受理的结果。
停止先禁用自动续接、停止助手，再尝试取消正在排队/执行的生成任务；已经提交到供应商的调用以任务系统的取消能力为准。

| 端点 | 说明 |
| --- | --- |
| `GET /assistant/status` | 免身份的宿主状态查询（不含任何凭据）；未就绪时返回明确原因而不是空回复 |
| `POST /assistant/ui-session` | 签发短期限 UI 会话凭据；需本机同源，并且能出示 owner 凭据（或显式本地引导开关） |
| `POST /assistant/chat` | NDJSON 流式对话：`text_delta` 正文、`lifecycle` 整理/重试、`tool` 执行进度 + 一次 `turn_end` 结算；`tool` 的 `phase` 为 `start/update/end`，仅传 `toolCallId/tool` 与结束时的 `isError`，不传参数和结果；结算与历史包含 `toolActivity`，未结束调用记为 `interrupted`。可带 `references: [{kind,id}]` 追加已校验的素材/画布引用；宿主凭据与模型密钥由后端注入，页面不接触 |
| `POST /assistant/cancel` | 取消指定画布正在进行的回合 |
| `POST /assistant/steer` | `{canvasId,sessionId,turnId,instructionId,message}`：追加当前回合要求；Go 校验本人尚未结算的回合，宿主校验当前会话与正在执行的轮次，使用官方 pi 指令队列。相同编号与文本重试不重复入队；不同文本复用编号拒绝。素材范围和技能版本继续沿用本轮快照 |
| `GET/PUT /assistant/host/config`、`POST /assistant/host/start|stop` | 宿主生命周期：需 owner 凭据 + 本机同源；启动命令只取本机配置，绝不接受请求体传入的可执行命令 |

正文的 `text_delta` 带 `messageId`，消息结束的 `assistant_message` 包含 `messageId/text`，用于分开执行说明和最终回复。结算及历史轮次包含 `execution`（正文消息与工具身份的有序列表）、`finalMessageId` 和 `metrics`（`firstTokenMs/totalMs/requests/toolSteps`）。用时取宿主实际处理时间；页面不根据记录数量估算。过程记录不包含模型思考、工具参数或工具结果。

按轮撤销不依赖浏览器流或宿主的最后一条消息：轮前文档由后端在转发前落盘，变更摘要由该轮自己的写入回执重建，
因此浏览器断流（没有 `turn_end`）、用户取消或后端在回合中途重启之后，已经落地的助手写入仍然可以撤销。

### 上下文、执行中补充与恢复

每轮由 Go 注入当前工程的可信概览：画布名称、版本、对象数量和选区概览，不携带图片正文、完整提示词或数据 URL。
剪辑上下文包含当前工程与版本、选区、画面尺寸、时长、有限片段概览和最近五项原生修改记录；时间线、字幕和场景正文按需读取。
客户端提供的概览不能替代后端数据。模型还会获得最近三轮的有限操作回执和任务引用。

超过 12000 字符的工具文本保存到该官方会话的私有 `tool-results` 目录，模型先看到结果编号、任务/候选等身份与前 1600 字符预览。
`tool_result_read` 按字符偏移读取最多 6000 字符，或搜索并读取命中附近内容；原始文件不截断，结果编号仅在所属会话可读。
页面和模型不能指定任意文件路径。分页读取计入本轮工具预算；结果是历史快照，不能作为当前工程版本。

流开头的 `turn_start` 给出 `turnId/sessionId`。补充指令状态为 `queued`（等待工具边界）或 `received`（已交给模型），通过 `instruction` 事件实时更新。
`received` 不代表已按要求修改成功。结束和历史中的 `instructions` 保留原文与状态；停止或退出前尚未处理的指令显示 `not_processed`，清空官方队列，避免进入下一回合。
执行中仅补充当前任务要求；新增素材授权或切换技能需要另发一轮。

`GET /assistant/history` 返回 `activeTurn` 或 `null`。活动回合包含 `execution`（已有正文和工具顺序）、`toolActivity`（实际运行状态及经过过滤的输入／结果详情）和 `lifecycle`（思考、重试或压缩状态，不含推理正文）。重新进入时先加载运行端快照，再通过既有历史刷新持续更新；不把运行中的调用标成中断，不重复启动模型轮次。断流、停止后与页面重开时，界面读取活动回合并追踪最终记录，不自动重放 `chat`。
每次工具开始和完成写入同一官方 SessionManager 的检查点，重开后可恢复已完成操作和任务/候选引用；不把缺少完成记录的调用判为成功。
恢复制作仍需查询真实任务和工程历史，沿用现有操作回执、生成步骤身份和候选重复入轨保护；已受理的外部生成是否完成由原任务状态决定。
剪辑读取正文和版本在同一工程锁内完成。人工修改后，冲突写入仍拒绝；只有明确重读当前内容后，后续修改才使用新版本。
宿主默认不设每轮模型请求次数或工具步数上限。显式设置正整数时，`BEEFTV_AGENT_MAX_REQUESTS_PER_TURN`、
`BEEFTV_AGENT_MAX_TOOL_STEPS_PER_TURN` 仍可限制对应额度，按轮独立计数、下一轮从零开始；达到额度时保存真实未完成原因。停止、单轮超时与无进展超时继续有效；总预算
`BEEFTV_AGENT_TOTAL_REQUEST_BUDGET` 默认关闭，只有显式配置才启用。

### 外部客户端连接

桌面设置的「外部 Agent」提供 Codex、Claude Code、Claude Desktop、Cursor 及其他 MCP 客户端的接入配置。Claude Desktop 使用开发者设置中的 `mcpServers` JSON；Claude Code 使用终端命令，Windows 命令需在 PowerShell 运行。保留其他 MCP 服务配置，连接时保持 Seal 开启。

配置固定使用随包 CLI 的绝对路径和 `BEEFTV_DATA_DIR`，避免客户端继承的环境选错工作区。Windows CLI 为主程序旁的 `cli/beeftv.exe`，不要把桌面主程序 `Seal.exe` 用作 MCP 命令。安装文件不完整时，`POST /agent-clients` 返回 412 / `cli_unavailable`，不签发凭据；重新下载并完整解压后重试。

MCP 使用官方 Go SDK 的 stdio transport；stdout 只写协议消息，启动诊断写 stderr。未发现运行实例时返回 `runtime_not_found`，不猜测默认端口；读取操作清单的启动等待上限为 5 秒。

Windows 的运行地址描述文件位于用户目录的 `.beeftv/runtime/`，按数据目录的规范化路径摘要分开保存，并校验工作区身份。该位置在 AppData 外，客户端不再读取 AppData 中旧的 `runtime.json`，避免 Microsoft Store/MSIX 客户端的私有副本遮住真实实例。数据库和素材仍留在原工作区。升级后保持 Seal 开启，并在「外部 Agent」重新生成连接配置。

### 只读边界

桌面实例的已登记外部客户端使用自身 ID 与 Bearer 凭据访问 `/ops` 和 `/ops/:op`，不需要也不应持有桌面启动令牌。其凭据不能访问普通 REST 写接口或换取 UI 会话。内置 UI 会话签发另需 Wails 绑定提供的独立 `X-Beeftv-UI-Bootstrap` 凭据；仅有 `X-Desktop-Token` 不足以签发。

只读是**操作层与 MCP 的策略边界，不是操作系统级隔离**：同一台机器上持有 owner 凭据的进程本来就能直接访问数据目录，
因此只读模式的作用是「不让某个外部客户端或某个工具集拿到写能力」，而不是限制本机其他程序。

- 能力模式只由身份决定：已登记客户端的模式来自服务端登记，请求体与查询参数都不能提升或放宽它。
- `beeftv --read-only`（`ops list` 与 `mcp serve`）在客户端本地再次收紧：即使服务端返回了写操作，也只暴露 `readOnly` 操作。
- 服务端对写操作始终按登记权限拒绝只读客户端（`read_only_client`），不依赖客户端自觉。

## 生成确认与重放

`GET /assistant/history` 的每个轮次包含 `undone`，从当前用户和画布的持久化撤销回执读取。页面重开后仍显示已撤销；回执不存在或不属于该用户/画布时不泄露其状态。

`POST /tasks` 可在 `input.metadata.clientOperationId` 提交一次确认的稳定编号（8–128 个 ASCII 字母、数字、冒号、下划线或连字符）。相同用户、编号及完整原始请求返回已有任务；更换模型、提示词、素材、参数或项目时返回 409，不创建第二个任务。Trace ID 和 Request ID 不参与比较。任务回执丢失时以原编号和原请求重发；不要生成新编号猜测是否已接单。

旧任务若没有请求摘要，不能凭编号推断内容相同，因此拒绝重放，应先查询已有任务。此编号仅保证本地任务不重复创建，不代表上游扣费或取消结算已经确认。

## 任务诊断

章节分镜替换与角色候选写入可携带 `sourceTaskId`。服务端核对原任务、用户、项目、章节和生成类型，并将结果写入与稳定操作回执放在同一事务中。同一任务和内容重放返回原回执，不覆盖之后的人工编辑；更换内容返回 `409 operation_id_reused_with_different_payload`。分镜仍须提交批准时的 `expectedRevision` 与 `expectedShotIds`；冲突为 `409 project_revision_conflict` 或 `project_unit_shots_changed`。

`GET /projects/:id/chapter-apply-receipts?taskIds=` 查询最多 100 个任务的已提交回执。页面不以更新时间猜测是否写入；没有回执的分镜结果保留待核对，确认后可直接写入，不重新生成。

`POST /tasks/:id/query-provider` 用于取回失败视频任务的原有结果：校验归属、持久化的供应商任务 ID 和协议支持后，只查询状态及下载，不重新提交生成。恢复成功会保存任务结果并登记产物；正在处理时返回 `recovered=false`。没有原任务 ID 的记录不能凭本地 ID 自动找回。已发出但未取得回执的提交标记为 `submission_unknown`，阻止付费重试；明确限流、鉴权拒绝或尚未发送的请求保留对应错误类别。

NewAPI Channel 2 与 BeefAPI 视频的暂时下载断连会保留原任务 ID 并继续后台取回，自动恢复最长到任务开始后 24 小时；超出窗口后可在失败任务详情手动取回。任务日志接口提供脱敏的 `summary`，不返回原始 `message` / `payload` 内容；摘要不写回数据库。

任务列表与详情中的 `errorCode` 是 Seal 归类后的错误类别，不能当作上游原始代码。已识别的 SQLite 缺表/列、锁定、只读、I/O 和约束失败使用 `local_storage`，提示本地数据库无法读写、不自动重试；不能因为外层 HTTP 400 把它归为模型参数错误。判断只读取实际错误消息，不读取请求或提示词回显。新记录的失败任务可包含 `failureDiagnostics`：`source` 区分本地校验、上游 HTTP / 业务响应、本地结果处理及未知来源；`summary` 保存脱敏后的错误摘要，另带实际记录到的 `providerCode`、`httpStatus`、`param`、`requestId`、`providerTaskId`、`stage` 和 `capturedAt`。缺失信息不推断或补造。`createdAt` 是任务创建时间，`completedAt` 是结束时间，均不等于错误记录时间。

诊断字段在本地 schema v3 中以可空文本列保存，旧任务不补写原始错误，重试会清除上一轮诊断。任务列表、详情和画布的“复制排查信息”使用同一份诊断；复制内容不包含请求正文、提示词、凭据、素材 URL 或本地文件路径。`providerRequestId` 可能是供应商任务标识，在复制内容中标作“服务端关联 ID”，与 HTTP 请求 ID 分开。

`failureDiagnostics` 同时保留本轮执行证据：运行版本和平台、任务配置中的模型/尺寸/质量/数量、提示词长度、参考素材数量与图片大小、本地参考图限制，以及最多 8 次请求（首次及最近 7 次，省略数量另计）的发起状态、HTTP 状态、请求 ID、开始时间、耗时和字节数。任务配置不等于最终出站参数；协议可能转换或省略字段，核对实际发送值须凭请求 ID 关联请求日志。HTTP 200 仅表示收到响应；`executionResult=completed` 才表示生成处理完成。转后台回查时状态为 `pending`，同一次任务继续累积有界轨迹并保留首次请求。成功任务也保存这些证据，以便区分后续本地保存失败或画布应用失败（复制内容来源为 `client_result`）。请求轨迹覆盖统一 Provider HTTP 客户端；旧记录、未经过该客户端的插件请求或上游未提供的 ID 仍可能缺失，不能仅凭空轨迹推断未发送。

## 剪辑工程与统一资产库

独立剪辑工程通过 `GET /editing-projects` 列出，`POST /editing-projects` 使用 `{ title, operationId }` 新建，`GET /editing-projects/:projectId` 读取，`PATCH /editing-projects/:projectId` 使用 `{ title }` 重命名。接口校验本机可信界面与当前工作区归属；新建操作身份重放返回同一工程，不创建隐藏画布。工程编号使用 `cut_` 前缀，视频源与原生编辑历史在编辑运行端保存。

本机入口 `POST /edit-projects/:canvasId/open` 接收 `{ parentOrigin, theme }`，返回现成 Studio 的一次性启动票据；`theme` 为产品的 light/dark。这个既有路径参数在独立剪辑页填写 `cut_` 工程编号。操作继续使用 `/edit-projects/:canvasId/edits/:editId/*action`，Go 校验当前用户工程归属，运行端再次校验源工程编号与编辑工程对应关系。独立剪辑工程和画布工程分别保存，只通过统一资产库共享媒体。

- `POST .../assets/import` 接收 `{ assetId, operationId, expectedRevision }`。后端从当前用户资产记录读取 `data.storageKey`，再读取所属本地 READY 资源；不接收浏览器提供的 URL、文件路径或资源元数据。图片默认 5 秒，视频和音频使用资源记录的时长，追加到工程末尾。当前支持 PNG/JPEG/WebP/GIF、MP4/WebM、WAV/MP3/OGG/M4A，单文件最多 512 MB；缺失时长、尺寸或不支持的格式会明确拒绝。工作工程保存独立素材副本及资产/资源编号，导入遵循版本校验、幂等和原生撤销。
- `GET .../exports` 返回持久导出编号、输入版本、日期、格式及状态。不会返回本地文件路径。
- `GET .../exports/:exportId/file` 只下载所属工程已完成的 MP4。前端通过原有资源上传与资产持久化流程保存成片，同一导出使用固定上传身份和固定生成效果身份；等待实际资产写入回执后才显示已保存，重开后的重复保存也确认后端持久化。

嵌入 Studio 的所属会话可调用运行端 `POST /api/beeftv/add-text` 添加标题或字幕：接收 `{ text, start, duration, caption }`，批量字幕使用 `cues: [{ text, start, duration }]`。最多 1000 条，每条文字不超过 4000 字符，时间必须有限且位于一天内。该接口仅存在于当前工程的 Studio 网关中，继续要求所属会话 Cookie、同源请求、版本头和操作编号，通过工程事务与原生历史保存；不会接受文件路径或执行用户代码。

新导出文件位于对应冻结导出目录，列表与下载不依赖 Studio 的短期内存任务列表。重新打开已完成结果可读取文件；进程中断时进行中任务的恢复仍待实现。完整桌面包的按钮、来源和 Cookie 联调仍需验收。

### Hypit 制作与候选

`POST /edit-projects/:canvasId/production` 打开当前项目制作工程，返回 `editId`、剪辑版本、Hypit 版本、作者文件哈希及素材输入清单，不创建新的 Agent 会话。下列操作均是 POST，位于 `/edit-projects/:canvasId/edits/:editId/hypit/`：

| 操作 | 请求与结果 |
| --- | --- |
| `open` | 读取制作工程身份、文件哈希和已导入输入 |
| `read` | `{ area: "skill" | "project", file }`，返回允许的官方参考或作者文件内容与 SHA-256 |
| `write` | `{ file, text, expectedHash, operationId }`；新文件用 null，已有文件必须匹配旧哈希；限制作者文件类型、禁止包安装和凭据配置 |
| `assets/import` | `{ assetId, operationId, expectedRevision }`；从已保存的所属本地资源复制，返回相对文件路径和 `inputId`，不修改剪辑轨道 |
| `frames` | `{ inputId, times? }`；图片一帧，视频最多八个有效时刻；返回真实 JPEG 帧，音频不支持画面提取 |
| `start` | `{ command: "check" | "plan" | "build", source, operationId, expectedRevision, compositionOutput?, timelineOutput? }`；source 为显式 SVRun，冻结输入后调用实际 Hypit，返回任务身份 |
| `status`、`cancel` | `{ jobId }`；查询实际执行状态或取消。提交不等于制作完成 |
| `list` | 列出所属制作任务；重启后失去执行进程的任务标记 interrupted，保留输入和结果 |
| `publish` | `{ jobId }`；只允许已完成的 build，检查结果哈希并产生不可变可编辑候选，不修改主轨道 |

制作运行端固定 Hypit 0.2.17，只配置本地媒体与 HyperFrames 执行端；新素材仍由现有生成提议、审批和资产流程提供。原生作者组件执行当前没有操作系统级沙箱。

`POST .../promote` 用 `{ candidateId, operationId, start?, track?, append?, replaceSceneId?, expectedRevision? }` 提交候选。默认校验制作时版本；`append=true` 在事务内计算末尾；`replaceSceneId` 只替换已有主片段并保留其位置、轨道和长度，候选过短拒绝。追加与替换不能同时指定。人工界面可明确选择当前审阅版本，内置助手不能传 `expectedRevision` 覆盖旧候选保护。后端根据已验证身份写入人工或 Agent 历史，忽略调用方自报的 actor。旧工作副本和候选保留供撤销恢复，不自动合并手动修改。

`POST .../history` 读取实际原生历史。Agent 的指定条目撤销通过已有 `POST .../mutate` 的 `route="history/undo"`，携带稳定操作身份、当前版本及条目编号；后续修改发生冲突时拒绝，Agent 工具不开放强制覆盖。

剪辑接口只接受受信任的本机界面或内置助手宿主。宿主必须出示仍开启、属于当前项目的后端回合；普通界面和已登记外部客户端不能借用回合头。素材导入在宿主调用时还要匹配该回合已经验证的素材范围。运行端再次校验编辑工程归属。这些检查不等同于跨进程取消与文件提交的数据库原子事务。

## 明确不存在的端点

`/auth/*`、`/admin/*`、`/payments/*`、`/wallet/*`、`/public/canvas-shares/*` 以及云存储配置端点不属于本地产品合同。

旧内置 Agent 的 `/agent/*` 端点已随该功能退场，历史运行、偏好和记忆数据仍保留在本地数据库中。通用任务接口会按产品边界拒绝 `cloud_agent`、`cloud_agent_step` 和 `agent_memory_compact`，不会把它们当作普通生成任务执行。

内置 BeefAPI 连接成功后，同一份企业凭证用于渠道请求和模型目录。企业连接、模型目录、Provider/Protocol 与自定义渠道不受 Agent 退场影响。

内置 BeefAPI 的 Seedance 视频任务由本机后端上传参考素材后再向上游提交链接；浏览器不直接访问该上传接口，也不把整份参考文件放进本地 `/tasks` 请求。本机已保存的参考文件即使工作区已有公开访问地址，也仍由本机后端上传后再提交链接。失败时不会自动重提生成。

## HyperFrames 本地创作接口

以下路径均位于 `/api/edit-projects/:projectId/edits/:editId`，要求可信本机 UI，或属于当前项目的开放助手轮次。
编辑运行端再次核对 `editId` 与项目归属，不接收客户端指定的 CLI 路径、任意命令或工作目录。

| POST 路径 | 请求与行为 |
| --- | --- |
| `/hyperframes/context` | 当前时间线、选区、尺寸、fps 和版本 |
| `/hyperframes/candidate` | `baseRevision, html, css, script, duration, width, height, fps?, assets?`；创建不可变候选，素材绑定为 `{source,path}`，均为工程内相对路径 |
| `/hyperframes/candidates` | 列出已有候选，前端按 `kind=hyperframes` 展示动效结果 |
| `/hyperframes/inspect` | `candidateId, command`；仅允许固定 CLI 的 `lint/check/snapshot`，返回报告与实际 PNG |
| `/hyperframes/review` | `candidateId`；读取已有检查与画面，不重新执行 CLI |
| `/promote` | 共用入轨接口；要求候选内容完整、官方 check 浏览器实际运行通过且有截图，来源版本一致，写入原生历史 |
| `/hyperframes/export` | `operationId, expectedRevision, fps?, quality?`；质量为 `draft/standard/high`，通过现有 Studio 启动冻结 MP4 导出 |
| `/hyperframes/exports` | 读取本工程持久导出状态；已完成文件沿用原有 `/exports/:exportId/file` |

`/promote` 的人工提交可显式传当前 `expectedRevision`。助手传该覆盖字段会被拒绝，防止制作期间的人工编辑被静默覆盖。
`candidate_check_required` 表示候选没有完整且匹配内容的检查回执；`revision_conflict` 保留候选，供用户查看后处理。
官方 Skill 与 CLI 均固定 `0.8.130`；产品不提供任意 shell、远程安装、自动更新或云发布入口。
